## 背景（Context）

用户希望在“当前 session”中更快定位与当前项目路径相关的会话。现有 Sessions 列表按平台聚合后分页展示，但缺少按工作目录筛选的维度。由于历史会话可能分布在多个路径，新增筛选应保持“默认不过滤”，并在用户主动选择后执行过滤。

## 目标与非目标（Goals / Non-Goals）

**目标（Goals）：**
- 在 Sessions 区域增加路径分类 `select` 控件。
- 默认值为“全部路径”，保持当前行为不变。
- 路径分类项由后端查询同步返回。
- 前端传目录和分页参数后，后端返回对应目录下的分页会话结果。
- 保证与平台切换、分页加载、删除/恢复等已有行为兼容。
- very long path 在 UI 中可完整查看，不做截断隐藏。

**非目标（Non-Goals）：**
- 不实现多选路径过滤。
- 不实现路径模糊搜索与收藏。
- 不改动会话底层存储结构。
- 不新增跨平台统一路径规范化规则之外的复杂映射策略。

## 设计决策（Decisions）

1. 路径筛选由后端处理，前端仅传 `path_filter + offset + limit`。  
理由：查询语义一致，分页准确，避免前端全量拉取和重复计算。  
备选方案：前端拉全量后筛选。拒绝原因：性能和一致性不可控。

2. 查询流程采用“先同步查目录列表，再查会话分页数据”。  
理由：确保筛选项与结果同源，减少前后端状态偏差。  
备选方案：目录列表异步单独加载。拒绝原因：容易出现选项与数据不同步。

3. `select` 第一项固定为“全部路径（all）”。  
理由：保持默认兼容，不影响现有用户习惯。  
备选方案：默认选中当前工作目录。拒绝原因：可能导致“看不到其他会话”的认知偏差。

4. 缺失路径的会话归类为“未知路径”。  
理由：保证数据不丢失，用户可解释。  
备选方案：仅在“全部”显示。拒绝原因：用户无法单独聚焦此类异常数据。

5. 切换平台时，路径筛选重置为 `all`。  
理由：不同平台路径集合不同，重置可避免“旧筛选值无结果”的困惑。  
备选方案：保留上次筛选值。拒绝原因：跨平台路径语义不一致，容易形成空列表误解。

6. very long path 不做截断，需完整可见。  
理由：路径本身是辨识关键，截断会影响判断。  
备选方案：截断 + tooltip。拒绝原因：增加交互成本且不满足“直接完整可见”的需求。

## 详细方案（Implementation Design）

### 1. 接口与参数

- 扩展/新增 Sessions 查询命令（Tauri）：
  - 输入：`platform_id`, `path_filter`, `offset`, `limit`
  - 输出：
    - `paths`: 当前平台的目录列表（包含 `all` 与 `unknown` 映射）
    - `sessions`: 当前筛选下分页结果
    - `pagination`: `total`, `offset`, `limit`, `has_more`
- `path_filter` 约定：
  - `all`：不过滤
  - `unknown`：仅缺失路径
  - 其它：精确匹配具体路径

### 2. 后端查询流程

- 每次会话列表请求按以下顺序执行：
  1. 基于 `platform_id` 聚合/扫描可见会话，提取目录集合并去重排序。
  2. 根据 `path_filter` 对会话集合过滤。
  3. 对过滤后的结果应用分页（`offset/limit`）。
  4. 返回目录列表与分页结果。
- 目录列表与会话结果使用同一批源数据，避免不一致。

### 3. 前端状态与交互

- 前端状态保留：
  - `selectedPathFilter`（默认 `all`）
  - `pathFilterOptions`（来自后端 `paths`）
- 用户切换路径时，重新请求后端列表（携带新 `path_filter`，并重置 `offset = 0`）。
- 平台切换时：
  - `selectedPathFilter` 重置 `all`
  - 请求后端拿该平台目录列表与第一页会话。

### 4. UI 展示策略（长路径）

- 路径筛选下拉项与会话路径展示均不做截断省略。
- 允许控件/列表项通过换行或横向滚动承载完整路径，确保路径文本可直接完整读取。

### 5. 数据兼容性

- 若当前平台会话摘要未稳定暴露路径字段：
  - 在 `src-tauri/src/session/*` 统一补充 `path` 字段（字符串或 `null`）。
- 各平台路径提取规则保持最小差异化，统一在聚合层输出。

### 6. 本地化文案

- 新增 i18n 键：
  - `sessions.pathFilter.label`
  - `sessions.pathFilter.all`
  - `sessions.pathFilter.unknown`
  - `sessions.pathFilter.empty`

## 风险与权衡（Risks / Trade-offs）

- [后端查询复杂度提升] -> 缓解：复用现有平台扫描逻辑，先保证正确性再做索引优化。
- [目录列表同步查询增加响应时间] -> 缓解：按平台缓存目录摘要并设置失效策略。
- [路径格式不一致（大小写/尾斜杠）] -> 缓解：基础规范化（trim、统一分隔符）；保留原值用于展示。
- [长路径完整显示造成布局压力] -> 缓解：通过换行或横向滚动处理，不牺牲可读性。

## 迁移计划（Migration Plan）

- 后端先实现“路径列表 + 按路径分页查询”统一返回。
- 前端改为参数驱动请求（`path_filter + offset + limit`），移除前端全量筛选逻辑。
- 增加本地化文案与回归测试。

回滚方案：
- 回退到原有无路径筛选查询接口与前端展示。
