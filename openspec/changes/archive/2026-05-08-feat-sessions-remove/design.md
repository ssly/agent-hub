## 背景（Context）

Sessions 标签页当前已支持 Claude Code、Codex CLI、Kiro 三个平台的会话列表、分页、消息查看和恢复，但尚无删除能力，导致陈旧会话持续累积并降低可用性。项目中已有破坏性操作的二次点击确认模式（例如删除 skill / 删除 MCP / 回收站操作），本次变更应对齐该行为，以保证一致性与安全性。

各平台的会话存储方式不同：
- Claude Code：会话文件位于 `~/.claude/projects/...`
- Codex CLI：线程记录位于 `~/.codex/state_5.sqlite`（查询时过滤 `archived = 0`）
- Kiro：元数据与消息文件位于 `~/.kiro/sessions/cli`

## 目标与非目标（Goals / Non-Goals）

**目标（Goals）：**
- 在 Sessions 标签页增加会话删除操作。
- 执行删除前强制两步确认。
- 删除后确保列表/分页状态更新且 UI 不冻结。
- 后端到前端返回清晰的成功/失败反馈。
- 在所有支持平台上保持一致行为。

**非目标（Non-Goals）：**
- 本次变更不包含批量删除。
- 本次变更不包含会话撤销/回收站能力。
- 除新增删除控件外，不改动 Sessions 页面布局。
- 不改动消息解析与恢复逻辑。

## 设计决策（Decisions）

1. 新增 Tauri 命令 `delete_session(platform_id, session_id)`。
理由：将各平台删除逻辑统一放在 Rust 会话模块中，复用已有文件系统/数据库访问能力。
备选方案：前端按平台分别删除。拒绝原因：逻辑重复且安全性更弱。

2. 在 `src-tauri/src/session/` 下实现平台删除适配器。
理由：现有模块在列表与消息查询时已按 `platform_id` 分支，删除应遵循同一结构。
备选方案：单一通用删除例程。拒绝原因：各平台存储模型差异明显。

3. Codex CLI 采用软删除语义（标记 archived），文件型平台执行物理删除。
理由：Codex 当前已依赖 `archived = 0` 过滤会话，归档可低风险从 UI 移除且更稳妥；Claude/Kiro 为文件存储，删除会话产物即可。
备选方案：直接硬删除 Codex 数据库行。拒绝原因：破坏数据库完整性的风险更高，且不清楚上游假设。

4. 复用 Sessions UI 现有二次点击确认交互。
理由：与现有破坏性操作体验一致，实现风险低，用户心智稳定。
备选方案：改用模态框确认。拒绝原因：本次目标是轻量接入并对齐当前模式。

5. 删除成功后刷新 Sessions 列表，并提供稳定的分页回退。
理由：删除后当前页可能出现空位，从当前选择重新加载可避免 UI 过期并保持统计准确。
备选方案：仅本地数组 `splice`。拒绝原因：总数与 `has_more` 可能失准。

## 风险与权衡（Risks / Trade-offs）

- [误触导致误删] -> 缓解：强制二次点击确认，并在短超时后自动重置。
- [平台删除行为不一致] -> 缓解：为各平台删除成功/失败路径补充明确测试。
- [Codex“删除”语义与文件删除不一致] -> 缓解：文档中明确 Codex 为“归档后从 Sessions 视图移除”。
- [分页列表在删除后状态漂移] -> 缓解：删除后统一重新拉取列表，并以后端返回重算 `offset/total/has_more`。
- [文件删除权限或 IO 错误] -> 缓解：后端返回可读错误文本，前端展示本地化失败提示。

## 迁移计划（Migration Plan）

- 实现后端命令与各平台删除处理器。
- 在前端 `api.js` 暴露调用，并补齐删除/确认/成功/失败 i18n 文案。
- 在 Sessions 卡片渲染中新增删除按钮与二次确认逻辑。
- 删除成功后触发列表重载。
- 在 Claude/Codex/Kiro 三平台进行手工验证并运行现有测试集。

回滚方案：
- 移除命令注册并隐藏 UI 删除入口，恢复现有列表/恢复行为。
